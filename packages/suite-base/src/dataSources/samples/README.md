# Lichtblick sample recordings

Open **Explore sample data** from the start screen or app menu. It lists the recordings of a catalog on R2, `catalog.json` in the `lichtblick-samples` bucket (`SAMPLES_CATALOG_URL`). Each recording streams from R2 and opens with its own layout. Each MCAP contains attribution and a description of the adaptations.

## Changing the samples

Nothing in this repository lists the samples. To add, replace or remove one, upload its MCAP, preview image and layout to the bucket and edit `catalog.json` there. The format is described in `components/Catalog/catalogUrl.ts`; relative URLs resolve against the catalog. Give a changed recording or layout a new file name (`grandtour-v2.mcap`), so browsers don't reuse a cached copy. Any other catalog opens the same way, with `?catalog=<url>` or by entering its `.json` URL on the start screen.

## Rebuild from publisher files

Run `uv run ci/create-dataset-samples.py <dataset> <input-directory>` at the repository root. Supply `--cloudini-converter <path>` for GrandTour and CitrusFarm. Use the Cloudini converter at commit `60ddb44740f24a8c4d9585d7e3764443ff7c385a` and the CMake build options documented in `ci/create-boreas-showcase.py`. The MCAP and its preview image are written to this directory by default, where git ignores them. With the recordings in this directory, `datasetSamples.test.ts` checks that every channel decodes.

- **DROID** uses the first episode of [the official face-blurred RLDS shard](https://storage.googleapis.com/gresearch/robotics/droid_100/1.0.0/r2d2_faceblur-train.tfrecord-00000-of-00031) as `droid.tfrecord`. Download `camera_serials.json`, `intrinsics.json`, `cam2cam_extrinsics.json`, and `droid_language_annotations.json` from the [authors' supplemental release](https://huggingface.co/KarlP/droid/tree/main). Prefix their local filenames with `droid-`. The three camera views are H.265, joint states are ROS 2 CDR, and task and arm commands are JSON. The time axis uses the published 15 Hz rate. The excerpt uses no model-generated depth.
- **GrandTour** uses [ETH-1, 2024-10-01-11-29-55](https://huggingface.co/datasets/leggedrobotics/grand_tour_dataset/tree/main/2024-10-01-11-29-55), from Unix second 1727775013 up to 1727775073. Extract the `data/` tar archives for `hdr_front`, `zed2i_left_images`, `zed2i_depth_image`, `tf`, `livox_points`, `anymal_state_odometry`, `dlio_map_odometry`, `prism_position`, `navsatfix_cpt7_ie_tc`, `anymal_imu`, and `anymal_state_actuator`. Keep the separate `images/` archives for `hdr_front`, `zed2i_left_images`, and `zed2i_depth_image` as `hdr-images.tar`, `zed-images.tar`, and `images-zed2i_depth_image.tar`. HDR and ZED are H.265. The HDR video was rectified with the supplied equidistant model, which is also stored as a separate calibration topic. Depth uses 16-bit compressedDepth PNG. Cloudini LiDAR keeps XYZ and intensity. Odometry positions are relative to each estimator's own first position. Leica measurements retain the original station frame.
- **CitrusFarm** uses [sequence 01_13B_Jackal](https://ucr-robotics.github.io/Citrus-Farm-Dataset/download.html) from Unix second 1689715612 up to 1689715672. Use the first bag for each modality, plus the second and third ZED bags (`zed_2023-07-18-14-27-17_1`, `zed_2023-07-18-14-27-46_2`) because each ZED bag covers only about 29 seconds. The converter expects the base and ADK bags as `base.part` and `adk.part`, the wheel odometry and ground truth bags as `odom.bag` and `gt.bag`, and the ZED, Blackfly and MAPIR bags with the original filename stems and a `.clip` extension. The inputs can be complete bags or byte ranges that start at the beginning of a complete `CHUNK` record and end right after a complete chunk. A range that starts inside a chunk cannot be read. If a range starts after an input's first chunks, prepend the bag's version line and header and provide its original footer connection records as a `.connections` sidecar. RGB, monochrome and red-green-NIR are H.265. Thermal is PNG, registered metric depth is compressedDepth PNG, and Velodyne XYZ and intensity are Cloudini. The mounting transform uses the [published LiDAR calibration](https://ucr-robotics.github.io/Citrus-Farm-Dataset/calibration.html).
